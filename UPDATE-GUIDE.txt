COJTGK CHURCHHQ — RESPONSIVE MODALS & ROLE ACCESS
================================================

IMPORTANT
---------
Keep a backup of your current files and Supabase database before deployment.
No Bible, image, or existing application data was intentionally removed from
this package.

INSTALLATION
------------
1. Open your Supabase project.
2. Go to SQL Editor.
3. Open SUPABASE-ROLE-ACCESS-MIGRATION.sql from this package.
4. Run the complete SQL file once.
5. Upload/replace index.html, style.css, app.js, Bible, and images on your host.
6. Sign in using an existing Administrator account.
7. Open Settings > User Roles & Page Access.

ROLE BEHAVIOR
-------------
- Administrator: complete View/Add/Edit/Delete access on every page.
- User: View access by default; Administrator may customize each page.
- Existing role=admin records are automatically kept as Administrators.
- Existing viewer/attendance records become User records, while their legacy
  role values remain compatible with the original database constraints.

SONG LIBRARY
------------
- The Song Library is shared by all signed-in users.
- View/Add/Edit/Delete are controlled by the Song Library permission row.
- The temporary Sunday lineup remains local to the current browser/device.
- Existing songs are not deleted or reassigned.

MOBILE BEHAVIOR
---------------
- Ordinary data tables become stacked record cards at 768px and below.
- Tapping a record opens its View action when one exists.
- The separate View button is hidden on mobile; Edit/Delete remain buttons.
- Page-level horizontal scrolling is disabled.
- Modals use a unified bottom-sheet layout on mobile.

FALLBACK / ERROR HANDLING
-------------------------
If the SQL migration has not been run, the application keeps the old role
behavior and Settings displays an instruction to run the migration. This avoids
silently changing or deleting existing records.
